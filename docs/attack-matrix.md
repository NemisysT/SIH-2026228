# Attack matrix

Each Module 1 attack class, the laboratory scenario that produces it, the
detector that assesses it, and the measured result.

All metrics come from `cvtrust lab evaluate` over the corpus generated by
`cvtrust lab generate --per-class 14` (336 clean samples, 6 classes, 4
contributors with differing acquisition characteristics). Reproduce with
`scripts/evaluate.sh`. **Evaluation population: synthetic attack-lab corpus** —
see the caveat at the end.

## Scenario structure

```
attack_lab/<scenario>/
├── dataset/            the only thing a detector ever sees
├── ground_truth.json   what was actually done, written OUTSIDE the root
└── attack_config.json  seed and parameters, sufficient to regenerate
```

Ground truth living outside the ingestion root is a structural guarantee, not a
convention: adapters walk the dataset root, so a ground-truth file inside it
would be visible to ingestion. Asserted by
`test_ground_truth_is_never_inside_the_dataset_root`.

## The matrix

| Attack class | Scenario | Seed | What it does | Detector | Signal |
|---|---|---|---|---|---|
| `duplicate_flood` | `duplicate_flood` | 101 | 14 byte-identical copies + 8 re-encoded pixel-identical copies of one source image | `exact_duplicate` | SHA-256 over bytes and over decoded pixels |
| `near_duplicate_flood` | `near_duplicate_flood` | 202 | 18 variants: exposure ±8%, JPEG quality 62–95, centre crop 0–5%, sensor noise | `near_duplicate` | pHash Hamming ≤8/64, confirmed by feature cosine ≥0.90, union-find clustering |
| `label_flip` | `label_flip` | 303 | 30% of one contributor's labels changed to a uniformly-random different class | `label_consistency` | Distance-weighted k-NN disagreement ≥0.70 + class-centroid margin |
| `systematic_mislabel` | `systematic_mislabel` | 404 | One contributor maps 85% of `vehicle` → `building` | `systematic_mislabel` | Directional concentration, one-sided binomial vs leave-one-out cohort, BH-corrected |
| `ood_insertion` | `ood_insertion` | 505 | 24 samples from a different renderer: thermal palette, inverted object polarity, heavy vignette, fixed-pattern row noise | `ood` | Mahalanobis + k-NN + PCA residual vs declared reference, Bonferroni-corrected quantile thresholds |
| *(multi)* | `combined` | 606 | delta floods near-duplicates **and** inserts alt-sensor imagery; charlie applies a systematic mapping; bravo flips labels | all | plus contributor aggregation |

### Reading the two numbers that look bad

**`label_flip` precision 0.250 in `combined`.** All 16 false positives are
out-of-distribution samples whose labels are *correct*. A sample from a
different sensor has an unrepresentative neighbourhood, so label disagreement is
the expected consequence rather than evidence of a flip. The pipeline recognises
this: the OOD detector runs first, and `label_consistency` qualifies such
findings explicitly — severity capped to `LOW`, with the reason recorded as an
evidence item pointing the analyst at the OOD finding for the same asset. The
result is visible in the next column: **`P(actionable)` = 1.000** — every
label finding an analyst would act on is correct. The finding is kept rather
than suppressed, because deleting a real observation is worse than qualifying
it. Cross-detector evidence fusion proper is Module 4.

**`systematic_mislabel` recall 0.750 / 0.667.** This is *sample-level* recall:
which specific samples the system attributes to the mapping. The claim this
detector actually makes is the contributor-level one, and that is exact in both
scenarios — the correct contributor, the correct direction
(`building` ← `vehicle`), at q ≈ 1e-19. Sample attribution is downstream of the
label detector's screening and inherits its recall.

**`ood_insertion` FPR clean 0.0089** against a configured family-wise target of
0.0100. The threshold means what it says.

## Clean-corpus false-alarm baseline

The number that matters most: behaviour on data with nothing wrong with it.

| Corpus | Samples | Findings | Distinct samples flagged | Rate | Overall assessment |
|---|---|---|---|---|---|
| `attack_lab/_clean` | 336 | 4 | 3 | **0.89%** | REVIEW RECOMMENDED |

All four are `LOW`-severity `ood_insertion` findings — reference-distribution
tail samples, which is exactly what a 1% nominal false-positive rate is supposed
to produce. Zero `duplicate_flood`, `near_duplicate_flood`, `label_flip`,
`systematic_mislabel` or `metadata_inconsistency` findings; zero `HIGH` or
`CRITICAL`; zero `QUARANTINE`. Asserted by four tests in
`tests/integration/test_pipeline.py`.

## Evasion matrix

| Evasion attempt | Result | Test |
|---|---|---|
| Re-encode into another container | **Detected** (content digest) | `test_re_encoding_does_not_hide_an_exact_duplicate` |
| Strip metadata, re-encode at quality 100 | **Detected** | `test_metadata_stripping_does_not_hide_an_exact_duplicate` |
| Exposure/contrast/noise/variable JPEG | **Detected** ≥8/10 | `test_photometric_perturbation_does_not_hide_near_duplicates` |
| Flood near-copies to manufacture agreement for a flipped label | **Defeated** | `test_flooding_cannot_manufacture_agreement_for_a_flipped_label` |
| Spread the campaign across all contributors | Aggregation diluted; **sample findings survive** | `test_spreading_an_attack_over_many_contributors_still_yields_findings` |
| Rotate near-duplicates 90/180/270° | **Not detected** — documented limitation | `test_rotation_defeats_near_duplicate_detection_as_documented` |
| Rename an entire class | **Not detected** — documented limitation | `test_a_uniformly_mislabelled_class_is_not_detectable_as_documented` |
| Oversized dataset | **Refused**, coverage `NOT_ASSESSED` | `test_a_dataset_too_large_for_exact_pairing_is_refused_not_approximated` |

The last three are assertions that a *claimed limitation is still true*. If a
future change made rotation detectable, those tests fail and the documentation
must be updated — coverage claims and code cannot drift apart silently.

## Performance

Measured on one laptop CPU core (Apple Silicon, Python 3.13), 128×128 imagery,
single-pass decode:

| Stage | Cost |
|---|---|
| End-to-end scan, 336 samples | ~70 ms detectors + ~1.2 s ingest/features |
| Throughput (detectors only) | ~4,800–5,400 samples/s |
| Dominant detector cost | `ood` (~77 ms), then `label_consistency` (~4 ms) |
| Full 6-scenario evaluation | ~9 s |
| Full test suite (182 tests) | ~75 s |

Near-duplicate search is exact all-pairs; peak memory is `block × n` bytes
rather than `n²`. Above `near_duplicate.max_pairwise_samples` (default 50,000)
the detector refuses rather than approximating.

---

**Evaluation population caveat.** Every number above was measured on a
*synthetic* corpus generated by `cvtrust.attack_lab.synth` under published
seeds. The corpus is the only kind where clean ground truth is known with
certainty, which is what makes a false-positive rate meaningful — but it is not
operational imagery. These are evidence that the detectors behave as designed
and a defensible lower bound on evidence quality. They are not a prediction of
operational performance, and recalibration against representative data is a
deployment step. This caveat is printed by the tool itself, not only here.
